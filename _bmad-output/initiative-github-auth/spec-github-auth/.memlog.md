- (direction) Пользователь выбрал slug github-auth и режим express.
- (note) Источник: запрос пользователя в чате 2026-10-07 + код (app/main.py, app/db.py): FastAPI, SQLite, таблица notes без владельца, аутентификации нет.
- (decision) Why: сейчас пользователь один и аутентификации нет; нужно, чтобы каждый входил своим GitHub-аккаунтом и видел только свои заметки.
- (capability) CAP-1 вход через GitHub: intent — человек входит своим GitHub-аккаунтом; success — после OAuth-потока на 127.0.0.1:8000 он видит свои заметки и свой GitHub-логин в интерфейсе.
- (capability) CAP-2 изоляция заметок: intent — пользователь видит и меняет только свои заметки; success — заметка A не видна B ни в списке, ни в поиске, ни по прямому URL просмотра/правки/удаления.
- (capability) CAP-3 выход: intent — пользователь может выйти; success — после выхода страницы заметок недоступны без нового входа.
- (capability) CAP-4 перенос существующих заметок: intent — заметки, уже лежащие в базе, отходят первому вошедшему; success — первый вошедший видит все прежние заметки, второй — ни одной из них.
- (constraint) Ключи OAuth App берутся из .env (GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRET) и не попадают в код и репозиторий (.env в .gitignore).
- (constraint) Callback зарегистрирован как http://127.0.0.1:8000/auth/callback — путь и хост фиксированы.
- (constraint) Существующие заметки в notes.db не теряются при изменении схемы; путь к базе по-прежнему из NOTES_DB.
- (constraint) Тесты работают без обращения к реальному GitHub.
- (assumption) Неаутентифицированный посетитель страниц заметок перенаправляется на вход; публичных страниц, кроме входа, нет.
- (assumption) Чужая заметка по прямому URL отвечает 404, а не 403, чтобы не раскрывать её существование.
- (assumption) Пользователь идентифицируется по неизменному GitHub user id, а не по логину.
- (assumption) Запрашивается только профиль; дополнительные scope GitHub не нужны.
- (question) Кто может входить: любой GitHub-аккаунт или только разрешённые логины?
- (question) Сколько живёт сессия: до закрытия браузера или N дней?
- (decision) Non-goals: другие провайдеры и вход по паролю; совместный доступ к заметкам; роли и админка; деплой на домен с HTTPS; GitHub API сверх профиля.
- (decision) Success signal: двое с разными GitHub-аккаунтами входят по очереди; первый видит прежние заметки, второй пустой список; заметки не пересекаются; после выхода главная требует входа.
- (assumption) OAuth-поток проверяет параметр state против подделки callback (стандартная защита OAuth).
- (question) Откуда брать секрет для подписи сессии: добавить в .env (например SESSION_SECRET) или генерировать при старте (тогда сессии сбрасываются при перезапуске)?
