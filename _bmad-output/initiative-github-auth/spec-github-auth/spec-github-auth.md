# Вход через GitHub

## Why

Боль: приложение заметок (FastAPI + SQLite) не знает, кто им пользуется, — аутентификации нет, у заметок нет владельца. Пока пользователь один, это терпимо; чтобы приложением могли пользоваться несколько человек, каждый должен входить своим GitHub-аккаунтом и видеть только свои заметки, а накопленные заметки не должны потеряться.

## Capabilities

- **CAP-1**
  - **intent:** Человек входит в приложение своим GitHub-аккаунтом.
  - **success:** После OAuth-потока на http://127.0.0.1:8000 пользователь попадает на главную, видит свои заметки и свой GitHub-логин в интерфейсе.
- **CAP-2**
  - **intent:** Пользователь видит и меняет только свои заметки.
  - **success:** Заметка пользователя A не видна пользователю B ни в списке, ни в поиске, ни по прямому URL просмотра, правки или удаления.
- **CAP-3**
  - **intent:** Пользователь может выйти.
  - **success:** После выхода страницы заметок недоступны без нового входа.
- **CAP-4**
  - **intent:** Заметки, уже лежащие в базе, отходят первому вошедшему пользователю.
  - **success:** Первый вошедший видит все прежние заметки; второй пользователь не видит ни одной из них.

## Constraints

- Ключи OAuth App (`GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`) и секрет подписи сессии (`SESSION_SECRET`) берутся из `.env` и не попадают в код и репозиторий.
- Входить может любой GitHub-аккаунт, списка разрешённых нет.
- Сессия живёт 7 дней.
- Callback зарегистрирован как `http://127.0.0.1:8000/auth/callback` — путь и хост фиксированы.
- Существующие заметки в базе не теряются при изменении схемы; путь к базе по-прежнему задаёт `NOTES_DB`.
- Тесты работают без обращения к реальному GitHub.

## Non-goals

- Другие провайдеры входа и вход по паролю.
- Совместный доступ к заметкам.
- Роли и админка.
- Деплой на домен с HTTPS.
- Обращения к GitHub API сверх получения профиля.

## Success signal

- Двое с разными GitHub-аккаунтами входят по очереди: первый видит прежние заметки, второй — пустой список; созданные ими заметки не пересекаются; после выхода главная требует входа.

## Assumptions

- Неаутентифицированный посетитель страниц заметок перенаправляется на вход; публичных страниц, кроме входа, нет.
- Чужая заметка по прямому URL отвечает 404, а не 403, чтобы не раскрывать её существование.
- Пользователь идентифицируется по неизменному GitHub user id, а не по логину.
- Запрашивается только профиль; дополнительные scope GitHub не нужны.
- OAuth-поток проверяет параметр `state` против подделки callback.
