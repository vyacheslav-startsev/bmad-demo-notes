# Вход через GitHub и свои заметки

## Description

Приложение пускает только вошедших через GitHub, у каждой заметки есть владелец, пользователь работает только со своими заметками и может выйти; заметки без владельца принадлежат первому зарегистрированному пользователю. Требования — CAP-1…CAP-4 спецификации инициативы.

## Outcome

Двое с разными GitHub-аккаунтами пользуются приложением, не видя заметок друг друга, а прежние заметки остаются у первого вошедшего — success signal спецификации.

## Requirements

Источник — `spec-github-auth`, раздел Capabilities: CAP-1 вход, CAP-2 изоляция заметок, CAP-3 выход, CAP-4 перенос прежних заметок.

## Done when

1. Вход через реальный GitHub на http://127.0.0.1:8000 приводит на главную с логином пользователя в шапке; после выхода главная требует входа.
2. Заметка пользователя A не видна B в списке, поиске и по прямым URL просмотра, правки и удаления (тесты и ручная проверка).
3. Заметки, бывшие в `notes.db` до изменений, после первого входа принадлежат первому пользователю; второй их не видит.
4. `uv run pytest` проходит без обращения к реальному GitHub.
5. Ограничения спецификации соблюдены: секреты только в `.env`, сессия истекает через 7 дней, callback с неверным `state` отклоняется.

## Boundaries

Модуль `app/`, `seed.py` и тесты; схема `notes.db` меняется с сохранением данных. GitHub OAuth App и `.env` уже настроены и только потребляются. Non-goals — в спецификации.

## Notes

- Decision: 3 истории — вход/выход, владелец заметок, перенос прежних заметок; перенос отдельно как операция над данными (2026-10-07).
- Decision: заметки без владельца всегда принадлежат первому зарегистрированному пользователю и переходят к нему при его входе; другие пользователи их не получают (2026-10-07).
- Decision: `seed.py` пишет заметки первому пользователю, если он есть, иначе оставляет без владельца, и удаляет только заметки того, кому пишет (2026-10-07).
- Decision: эпика из 3 историй — закрывающий Refactor sweep не предлагается (правило: больше трёх записей) (2026-10-07).
- Decision: трассирующая история — запись 1 (OAuth → пользователь → сессия → логин в шапке); порядок 1 → 2 → 3, одна цепочка, параллели нет — все правят `app/main.py` и `app/db.py` (2026-10-07).
